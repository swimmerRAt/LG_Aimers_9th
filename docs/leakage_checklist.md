# 데이터 누수 점검표

각 피처는 모델에 넣기 전에 아래 표에 근거와 계산 시점을 기록한다. `확인 필요` 상태의
피처는 실험에 사용하지 않는다.

| 피처/피처군 | 투구 전 사용 가능 | 계산 기준 시점 | 현재 행 포함 여부 | 평가 test 다른 행 사용 | 상태/근거 |
|---|---:|---|---:|---:|---|
| 공식 경기 상황 컬럼 | 예 | 현재 투구 직전 | 아니오 | 아니오 | 데이터 설명서 명시 |
| 공식 `asof_*` 컬럼 | 예 | 현재 투구 직전 | 아니오 | 아니오 | 데이터 설명서 명시 |
| 현재 투구 실제 위치·구종·결과 | 아니오 | 투구 후 | 해당 | 해당 | 사용 금지 |
| train 기반 선수 target encoding | 조건부 | fold 학습 구간까지 | 아니오 | 아니오 | fold 내부 계산+smoothing 필요 |
| train rolling/expanding 통계 | 조건부 | 과거 행까지 | `shift(1)` 필수 | 아니오 | 정렬 키 검증 필요 |
| 실제 test 내부 빈도·분포·rolling | 아니오 | 평가 데이터 전체 | 해당 | 예 | 사용 금지 |
| Trackman 선수 단위 통계 | 확인 필요 | 2019–2024 | 아니오 | 아니오 | 메인 ID와 직접 교집합 0; 매핑 근거 필요 |

## 채택 전 필수 확인

- 학습 행의 모든 집계 피처가 같은 행의 타깃을 보지 않았는가?
- validation 시즌의 타깃 또는 분포가 전처리·인코더·보정기에 들어가지 않았는가?
- 같은 경기의 미래 투구가 과거 통계에 포함되지 않았는가?
- 평가 `test.csv`의 다른 행을 이용하지 않고 각 행을 독립적으로 예측하는가?
- cold-start 선수의 fallback이 fold 학습 데이터만으로 정의되는가?
- OOF Brier가 모든 고정 split에서 개선되고 split 편차가 기록됐는가?
